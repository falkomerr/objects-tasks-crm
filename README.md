# Контур · мини-CRM

React + TypeScript + Vite, Supabase Auth и PostgreSQL. Отдельного сервера приложения нет.

Работающее приложение: [https://objects-tasks-crm-rust.vercel.app](https://objects-tasks-crm-rust.vercel.app). Тестовые доступы передаются отдельно.

## Локальный запуск

Нужны Bun и работающий Docker. Первый запуск Supabase скачивает несколько контейнеров и может занять время.

```sh
bun install
bunx supabase start
bun run seed
bun run dev
```

Открыть адрес из вывода Vite (обычно http://127.0.0.1:5173). Seed создаёт .env.local с публичным ключом и .local/accounts.json с тремя тестовыми учётными записями. Эти файлы исключены из Git. Пароли генерируются случайно, выводить их в отчёты не нужно. Повторный seed использует существующие аккаунты и не дублирует объекты.

При первом старте миграции применяются автоматически. Для последующих изменений использовать bunx supabase migration up --local. Сброс базы удаляет локальные данные; после согласованного сброса также удалить .local/accounts.json перед повторным seed.

## Проверки

```sh
bun run typecheck
bun run lint
bun run build
bun test tests/workflow.test.ts
bun run test:security
```

Интеграционные тесты требуют запущенный Supabase и выполненный seed. Они работают только с localhost, создают собственный объект, затем логически удаляют его. Проверяют прямые запросы от пользователей, а не скрытие кнопок в UI.

## Защита

RLS фильтрует чтение четырёх таблиц. Прямая запись от anon/authenticated отозвана. Операции выполняют функции PostgreSQL, проверяющие роль и auth.uid(). Они не принимают автора, дату и исходный статус от клиента. Переход и история записываются атомарно под блокировкой строки. История не имеет клиентских операций записи. Профили и роли создаёт администратор.

Административный ключ используется только локальным seed, получающим его из Supabase CLI. В клиентскую сборку попадают только VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY.
